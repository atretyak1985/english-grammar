# Граматика англійської

Навчальний застосунок: правила англійської граматики українською, аналізатор
довільного тексту з підсвіткою часів, словник із Wiktionary і особистий кабінет
із прогресом.

Next.js 16 (App Router) · React 19 · Tailwind 4 · Drizzle + Postgres · Auth.js ·
Claude API. Контент тем — MDX.

> Раніше це був статичний сайт без збірки. Він переріс у застосунок: нижче
> описано те, що є зараз.

---

## Швидкий старт

```bash
make install          # залежності
make dev              # підніме Postgres у Docker і запустить сервер на :3000
```

Без `.env.local` теж працює — просто без входу, без кешу в базі й без розбору
моделлю. Це не «режим demo», а звичайний прохід із пропущеними шарами: кожен
зовнішній шар необовʼязковий.

### Налаштування

`.env.local` (у репозиторій не потрапляє, зразок — `.env.example`):

```
DATABASE_URL=postgres://eg:eg@localhost:5433/english_grammar
AUTH_SECRET=            # npx auth secret
ANTHROPIC_API_KEY=      # console.anthropic.com → API keys
ANTHROPIC_MODEL=        # необовʼязково; типово claude-sonnet-5
AUTH_GOOGLE_ID=         # необовʼязково — вхід через Google
AUTH_GOOGLE_SECRET=
EMAIL_SERVER=           # необовʼязково — вхід листом
EMAIL_FROM=
CONTACT_EMAIL=          # необовʼязково — адреса для запиту активації тарифу
```

Без `CONTACT_EMAIL` сторінка `/pricing` не показує кнопки з листом і прямо
каже, що канал звернення не налаштований: називати адресу, якої немає, гірше
за відсутність кнопки — той, хто хоче заплатити, написав би в нікуди.

Ключ Anthropic читає **тільки сервер**. Префікса `NEXT_PUBLIC_` тут не буває й
бути не може: він вшив би ключ у клієнтський бандл.

## Доступ і квоти

| Рівень            | Що доступно                                                                                                        | Ліміт слів аналізу / місяць |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------- |
| Гість (без входу) | Бібліотека (`/library`) — читання попередньо розібраних оповідань. Аналізатор довільного тексту закритий повністю. | 0                           |
| Вільний акаунт    | Усе, що гість, плюс аналізатор власного тексту, словник, прогрес, історія тестів.                                  | 5 000                       |
| Підписка `basic`  | Те саме, у більшому обсязі.                                                                                        | 100 000                     |
| Підписка `pro`    | Те саме, найбільший обсяг — для довгих текстів і книжок.                                                           | 500 000                     |

Цифри — з `src/lib/access/limits.ts` (`FREE_MONTHLY_WORDS`, `DEFAULT_PLANS`); ті
самі значення засівають рядки `plans` під час `make db-seed`, тому в коді й у
базі не може розійтися дві копії чисел. Витрачене рахується від таблиці
`analysisUsage` (`src/lib/access/index.ts`), а не від вікна в памʼяті процесу —
цифра переживає перезапуск застосунку. Кабінет (`/account`) показує залишок за
поточний місяць, `/pricing` — вітрину тарифів.

**Гостьовий трафік не витрачає ключ Anthropic.** Бібліотека (`/library`)
розібрана заздалегідь і лежить у базі (`stories`, `story_matches`): читач
бачить готову підсвітку часів, а виклик моделі стається один раз, під час
засіву, а не на кожне відкриття сторінки гостем.

### Засів бібліотеки й тарифів

```bash
make db-seed
```

Пише в базу оповідання з `src/content/library/<slug>/` (текст, розмітка й уже
пораховані `words`/`stats`/`frequency`) і рядки `plans` з `DEFAULT_PLANS`.
Працює **без `ANTHROPIC_API_KEY`**: розмітка приходить з артефактів
репозиторію (`matches.json`), а не з живого виклику моделі — тому засів
безпечно запускати в CI чи на щойно піднятій базі.

### Як додати книжку

Прямий виклик — переноси рядків тут працюють, бо зворотний слеш поза лапками:

```bash
npm run import-book -- --in book.pdf --slug my-book \
  --title "Назва" --author "Автор" \
  --source "Project Gutenberg" --license "public domain" \
  --source-url "https://..." --sort-order 2
npm run db:seed
```

Через `make` те саме доводиться писати **одним рядком**. Усередині `ARGS='…'`
зворотний слеш рядка не переносить, а лишається в значенні: Make тоді виконує
лише перший рядок, і решта аргументів гине.

```bash
make import-book ARGS='--in book.pdf --slug my-book --title "Назва" --author "Автор" --source "Project Gutenberg" --license "public domain" --source-url "https://..." --sort-order 2'
make db-seed
```

`scripts/import-book.mts` бере PDF (текстовий шар), `.txt` або URL і пише три
файли в `src/content/library/<slug>/`: `story.txt`, `story.json` і `matches.json`.
Шапку й підвал Project Gutenberg зрізає сам — інакше кількасот слів ліцензії
зсунули б межі всіх шматків і потрапили б у підсвітку як проза.

Головне, що робить цей скрипт, — рахує нарізку на шматки й наскрізну нумерацію
слів **тим самим кодом, що читалка** (`chunksOf`, `wordTokens`). Раніше це був
ручний крок, і зсув нумерації на одне слово розмічував не ту конструкцію на весь
залишок книжки, лишаючись невидимим на око. Тепер такого зсуву не може бути за
побудовою. Перед записом артефакт проходить той самий строгий парсер і ті самі
пʼять перевірок, які потім побачить засів, тому `import-book` не може написати
файл, який відкине `db:seed`.

Типово розмітку дають локальні правила — безкоштовно, без мережі й без ключа.
З `--review` кожен шматок додатково уточнює модель (потрібен
`ANTHROPIC_API_KEY`, платний виклик на шматок); шматок, на якому модель не
відповіла, лишається на локальних правилах, а не порожнім. Ручний рецепт
розмітки через Claude CLI лишається в
[`docs/library-prompt.md`](docs/library-prompt.md) — там же описано формат
`matches.json` і причини, з яких засів відмовляє.

**У бібліотеку йдуть лише тексти, які можна публікувати.** Сторінка `/library`
відкрита гостям, а `story.txt` лежить у git, тому поле `license` — не
формальність: книжка під копірайтом там означала б публікацію чужого тексту.
Project Gutenberg і подібні джерела public domain для цього годяться.

### Ручна активація підписки

```bash
make grant-plan EMAIL=you@example.com PLAN=basic MONTHS=1
```

Піднімає ліміт користувачу вручну: `scripts/grant-plan.mts` знаходить акаунт за
поштою (і НЕ створює його, якщо такого нема) і пише рядок `subscriptions` зі
`status: 'active'` та періодом на `MONTHS` місяців. Платіжного провайдера в
застосунку поки немає навмисно — це окрема робота; місце під нього вже є
(`subscriptions.activatedVia`), просто зараз туди пишеться `'manual'`.

## Як працює аналізатор

Два проходи, і перший ніколи не залежить від другого.

**Локальні правила** (`lib/analyzer/tenses.ts`) — пʼять шаблонів, які знаходять
Past Simple, Past Continuous і Past Perfect за один прохід зліва направо.
Працюють миттєво, без мережі, без ключа, на тексті будь-якого розміру. Це те,
що читач бачить одразу.

**Уточнення моделлю** (`lib/analyzer/review.ts`) — другий прохід, який знімає
те, чого шаблони не розрізняють: `a tired engineer` проти `he tired quickly`,
`had lunch` проти `had finished`, present perfect проти past perfect. Модель
повертає **номери токенів**, а не розмічений текст — інакше відповідь коштувала
б стільки ж вихідних токенів, скільки вхідних, і не лягала б на локальні токени.

Уточнення необовʼязкове. Немає ключа, немає бази, вичерпано ліміт, текст
задовгий — екран лишається на локальній розмітці, і це не помилка.

### Шматки замість цілої книжки

`lib/analyzer/chunks.ts` ріже документ по кінцях речень вікнами ~1500 слів.
Межі залежать **тільки від тексту**, а не від сторінок: сторінки рухомі, їх
знаходить замір, і привʼязка до них означала б нові платні виклики на кожну
зміну розміру вікна. Розбирається сторінка плюс один шматок уперед.

### Три шари кешу

`lib/analyzer/cache.ts`: памʼять процесу → Postgres → Claude. Ключ містить
модель і версію промпту, тому зміна промпту сама інвалідує старі відповіді.
Однакові запити в польоті зливаються: двоє з тим самим текстом дають один
виклик API.

### Батч на цілу книжку

`lib/analyzer/batch.ts`: після завантаження документ іде в Batch API — удвічі
дешевше, і поки читач дійде до тексту, розібрано вже все. Забирання результатів
**ліниве**, тим самим запитом, який і так приходить від читача: фонового
воркера немає й не потрібно.

Batch гарантує до 24 годин (заміряно: дрібні батчі ~3 хвилини, батч на сім
запитів Sonnet — понад дві години). Тому на нього не можна вішати нічого, чого
користувач чекає, і в коді так і зроблено.

### Вартість

Заміряно на шматку в 1500 слів: 7772 вхідних / 2030 вихідних токенів.

|                      | Синхронно | Батчем  |
| -------------------- | --------- | ------- |
| Шматок ~1500 слів    | ~$0.034   | ~$0.017 |
| Роман ~100 тис. слів | ~$2.3     | ~$1.1   |

Один раз на текст: кеш робить перечитування безкоштовним.

Модель обрано заміром, а не за замовчуванням: на контрольному тексті з пастками
Sonnet 5 дав ті самі сім конструкцій, що й Opus 5, а Haiku 4.5 пропустив два
звичайні Past Simple. Перемикається через `ANTHROPIC_MODEL`.

Системний промпт кешується. Мінімальний обсяг, який взагалі підлягає
кешуванню, — близько 1024 токенів: на 890 кеш мовчки не вмикався, тому промпт
доведено до 1534 разом із розібраними прикладами. Лог пише обидва боки
(`кеш −прочитано +записано`) — якщо запис росте, а читання стоїть, знижки немає.

## Як додати тему

1. Створіть `src/content/topics/<slug>/` із розділами в `sections/*.mdx`,
   а також `meta.ts`, за потреби `quiz.tsx`, `drills.tsx`, `diagrams.tsx`.
2. Зареєструйте розділи в `src/content/topics/index.ts`. Шлях у `import()` має
   бути **літеральним** — інакше MDX не потрапить у збірку й застосунок
   зламається в standalone-образі.
3. Додайте картку теми в `src/data/topics.ts`.

Розділ — це окрема сторінка; вигляд «усе одним полотном» складається з тих самих
файлів, тому другого джерела правди немає.

шари кешу, троттлінг, парсер wikitext.
