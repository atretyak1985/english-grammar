# Граматика англійської

Навчальний застосунок: правила англійської граматики українською, аналізатор
довільного тексту з підсвіткою часів, словник із Wiktionary і особистий кабінет
із прогресом.

Next.js 16 (App Router) · React 19 · Tailwind 4 · Drizzle + Postgres · Auth.js ·
Claude API. Контент тем — MDX.

> Раніше це був статичний сайт без збірки. Він переріс у застосунок: нижче
> описано те, що є зараз.

---

## Швидкий старт

```bash
make install          # залежності
make dev              # підніме Postgres у Docker і запустить сервер на :3000
```

Без `.env.local` теж працює — просто без входу, без кешу в базі й без розбору
моделлю. Це не «режим demo», а звичайний прохід із пропущеними шарами: кожен
зовнішній шар необовʼязковий.

### Налаштування

`.env.local` (у репозиторій не потрапляє, зразок — `.env.example`):

```
DATABASE_URL=postgres://eg:eg@localhost:5433/english_grammar
AUTH_SECRET=            # npx auth secret
ANTHROPIC_API_KEY=      # console.anthropic.com → API keys
ANTHROPIC_MODEL=        # необовʼязково; типово claude-sonnet-5
AUTH_GOOGLE_ID=         # необовʼязково — вхід через Google
AUTH_GOOGLE_SECRET=
EMAIL_SERVER=           # необовʼязково — вхід листом
EMAIL_FROM=
```

Ключ Anthropic читає **тільки сервер**. Префікса `NEXT_PUBLIC_` тут не буває й
бути не може: він вшив би ключ у клієнтський бандл.

## Як працює аналізатор

Два проходи, і перший ніколи не залежить від другого.

**Локальні правила** (`lib/analyzer/tenses.ts`) — пʼять шаблонів, які знаходять
Past Simple, Past Continuous і Past Perfect за один прохід зліва направо.
Працюють миттєво, без мережі, без ключа, на тексті будь-якого розміру. Це те,
що читач бачить одразу.

**Уточнення моделлю** (`lib/analyzer/review.ts`) — другий прохід, який знімає
те, чого шаблони не розрізняють: `a tired engineer` проти `he tired quickly`,
`had lunch` проти `had finished`, present perfect проти past perfect. Модель
повертає **номери токенів**, а не розмічений текст — інакше відповідь коштувала
б стільки ж вихідних токенів, скільки вхідних, і не лягала б на локальні токени.

Уточнення необовʼязкове. Немає ключа, немає бази, вичерпано ліміт, текст
задовгий — екран лишається на локальній розмітці, і це не помилка.

### Шматки замість цілої книжки

`lib/analyzer/chunks.ts` ріже документ по кінцях речень вікнами ~1500 слів.
Межі залежать **тільки від тексту**, а не від сторінок: сторінки рухомі, їх
знаходить замір, і привʼязка до них означала б нові платні виклики на кожну
зміну розміру вікна. Розбирається сторінка плюс один шматок уперед.

### Три шари кешу

`lib/analyzer/cache.ts`: памʼять процесу → Postgres → Claude. Ключ містить
модель і версію промпту, тому зміна промпту сама інвалідує старі відповіді.
Однакові запити в польоті зливаються: двоє з тим самим текстом дають один
виклик API.

### Батч на цілу книжку

`lib/analyzer/batch.ts`: після завантаження документ іде в Batch API — удвічі
дешевше, і поки читач дійде до тексту, розібрано вже все. Забирання результатів
**ліниве**, тим самим запитом, який і так приходить від читача: фонового
воркера немає й не потрібно.

Batch гарантує до 24 годин (заміряно: дрібні батчі ~3 хвилини, батч на сім
запитів Sonnet — понад дві години). Тому на нього не можна вішати нічого, чого
користувач чекає, і в коді так і зроблено.

### Вартість

Заміряно на шматку в 1500 слів: 7772 вхідних / 2030 вихідних токенів.

| | Синхронно | Батчем |
|---|---|---|
| Шматок ~1500 слів | ~$0.034 | ~$0.017 |
| Роман ~100 тис. слів | ~$2.3 | ~$1.1 |

Один раз на текст: кеш робить перечитування безкоштовним.

Модель обрано заміром, а не за замовчуванням: на контрольному тексті з пастками
Sonnet 5 дав ті самі сім конструкцій, що й Opus 5, а Haiku 4.5 пропустив два
звичайні Past Simple. Перемикається через `ANTHROPIC_MODEL`.

Системний промпт кешується. Мінімальний обсяг, який взагалі підлягає
кешуванню, — близько 1024 токенів: на 890 кеш мовчки не вмикався, тому промпт
доведено до 1534 разом із розібраними прикладами. Лог пише обидва боки
(`кеш −прочитано +записано`) — якщо запис росте, а читання стоїть, знижки немає.

## Як додати тему

1. Створіть `src/content/topics/<slug>/` із розділами в `sections/*.mdx`,
   а також `meta.ts`, за потреби `quiz.tsx`, `drills.tsx`, `diagrams.tsx`.
2. Зареєструйте розділи в `src/content/topics/index.ts`. Шлях у `import()` має
   бути **літеральним** — інакше MDX не потрапить у збірку й застосунок
   зламається в standalone-образі.
3. Додайте картку теми в `src/data/topics.ts`.

Розділ — це окрема сторінка; вигляд «усе одним полотном» складається з тих самих
файлів, тому другого джерела правди немає.

## Тести

`vitest`, поруч із кодом (`*.test.ts`). Покрито те, де помилка тиха: переклад
номерів слів у номери токенів, перевірка відповіді моделі, межі шматків,
шари кешу, троттлінг, парсер wikitext.

```bash
make test
```
